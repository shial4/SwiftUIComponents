# Android catalogue

The component library and catalogue support Skip Fuse only. Every first-party Skip module uses `mode: native`; Swift and SwiftUI compile natively for Android. There is no first-party Kotlin component implementation or transpiled adapter.

DynamicList shares native SwiftUI lazy stacks and cell-ID scrolling between iOS and Android. Use `scrollToIndex` in shared code. Its older point-offset overloads are Apple-only because Skip Fuse does not currently expose point-based ScrollPosition or scroll geometry.

`app/src/main/kotlin/Main.kt` is the unmodified app shell generated by `skip init --native-app` for ComponentCatalog. Keep component behavior in shared Swift. Regenerate the shell with Skip when its template needs an update.

## Run

Follow [Skip's setup guide](https://skip.dev/docs/gettingstarted/) and use matching Swift compiler and Android SDK versions. Start an emulator or connect a device, then run from the repository root:

```sh
skip doctor --native
SKIP_DYNAMIC_LIBRARIES=1 gradle -p Android :app:installDebug
adb shell am start -n com.swiftui.components.catalog/component.catalog.MainActivity
```

The checked-in Skip.env supplies development app metadata. The catalogue is an example, and its signing configuration comes from Skip's template.

## Verify native Swift separately

```sh
skip android build --product ComponentCatalog -Xswiftc -DSKIP_BRIDGE
```

When Xcode and the Swift Android SDK use different compiler versions, pass `--swift-version` and `--toolchain` to select a matching installed native toolchain. `--toolchain` takes the .xctoolchain directory, not its usr/bin subdirectory. A compatible host macOS SDK is also needed to compile SwiftPM build plugins. Set DEVELOPER_DIR and SDKROOT for that process when necessary; do not change the system Xcode selection.

If multiple installed SDKs match the Android target, use a temporary SDK search directory containing only the desired artifactbundle and pass it with `--swift-sdks-path`. For direct Swift builds, select the target alias such as `--swift-sdk aarch64-unknown-linux-android28`; selecting a multi-target SDK bundle by ID can choose a different architecture's resource directory.

Gradle needs both the JNI/Kotlin bridges generated by the host Skip build and the native Swift libraries. Never edit generated Kotlin or Gradle outputs; keep component behavior in Swift. A successful native Swift compile alone does not verify an Android app. Run the APK and check the component screens and interactions after building.

## Shared logic tests

The `Tests` package runs the same Swift logic tests on Android without the desktop launcher. Apple rendering fixtures live in `Tests/Rendering`, outside the native test target because Skip's source scanner also visits SwiftPM-excluded subdirectories. The root `swift test` command runs both groups. Keep `Tests/Package.resolved` in sync with the root lockfile when intentionally updating dependencies.

Native Android tests need a host that packages both the Swift test library and its generated JNI bridges. The standalone `skip android test --apk` runner does not include those bridges and cannot verify this suite. The pinned toolchain also needs upstream fixes for main-actor startup and native test-source discovery. Keep the tests enabled; a successful compile is not a passing Android logic run. The catalogue UI checks below run in the actual app independently of the test harness.

The catalogue pins SkipUI 1.66.3 and SkipFuseUI 1.19.4. These releases include the [path containment fix](https://github.com/skiptools/skip-ui/pull/593) and [drag-release endpoint fix](https://github.com/skiptools/skip-ui/pull/592).

Native Android logic-test verification is incomplete with the pinned Skip 1.9.20 toolchain and bridge versions. Relevant upstream fixes cover [main-actor test startup](https://github.com/skiptools/skipstone/pull/311), [test manifest discovery](https://github.com/skiptools/skipstone/pull/317), [symlink discovery](https://github.com/skiptools/skipstone/pull/318), and [UserDefaults projection](https://github.com/skiptools/skip-android-bridge/pull/44). The package does not pin unpublished patches. A follow-up dependency update should adopt releases containing these fixes together, synchronize both lockfiles, then rerun logic, UI and memory checks.

With those fixes available and a matching native toolchain configured, generate the bridges and run the native test module:

```sh
SKIP_DYNAMIC_LIBRARIES=1 swift build --package-path Tests \
  --scratch-path .build/android-tests --build-tests
SKIP_DYNAMIC_LIBRARIES=1 gradle \
  -p .build/android-tests/plugins/outputs/tests/SwiftUIComponentsTests/destination/skipstone \
  :SwiftUIComponents:connectedDebugAndroidTest
```

The native test target uses `SkipTest` and the Skip plugin; the root library becomes dynamic only for Skip bridge builds. Check the Swift Testing event report under the generated module's `build/outputs/androidTest-results/connected/debug/swt-events.jsonl`: Gradle reports one instrumentation wrapper, while the report must show every Swift test completing without issues.

## Runtime smoke checks

With the debug APK installed and adb on PATH:

```sh
python3 Android/verify_catalog.py --serial emulator-5554
```

This opens all 84 routes and checks Muscle Map tapping and drag painting, calendar sizing and selection, key-path and JSON integrations, checkbox and rating bindings, badge labels, counting formats, progress updates, and joystick drag/release. List checks cover both axes, all sizing modes, shrinking/empty data, and 10,000-cell jumps followed by selection and dragging. Storage checks synchronize two readers and restart the process. The script resets the example preferences to their defaults. Add `--screenshots Documentation/Images` to capture each Android demo for the README.

To measure repeated navigation in one app process:

```sh
python3 Android/verify_catalog.py --serial emulator-5554 \
  --memory-only --memory-cycles 5 --memory-report /tmp/catalogue-memory.json
```

Each cycle changes calendar styles while preserving selection, jumps through a 10,000-cell list, and switches muscle-map sides before returning to the catalogue. The report records native and Java heap allocations, PSS and RSS, both immediately and after two seconds idle. Compare settled cycles on the same device and build; a single memory reading is not a leak test or a cross-platform memory budget.

SkipUI 1.66.3 also includes the [saved-state weak-key fix](https://github.com/skiptools/skip-ui/commit/0ed282718976bedfe362fb1246d1411c0ee25026), which allows discarded navigation state to be released. Keep checking settled memory across repeated navigation when updating dependencies.

The script requires a newly written accessibility snapshot for every observation and retries transient dump failures. It never reuses the previous screen after a failed dump. The script fails on Android crash or not-responding dialogs. Run performance and memory checks without competing builds, and inspect the recorded heap trend separately from the interaction results.

The calendar release regression sends the final finger position only in the touch-up event and checks that the selected range includes that day. SkipUI 1.66.3 contains the upstream fix; keep this check enabled to catch regressions.

The cross-month year-grid drag after scrolling remains a known limitation in 1.0.7: selection can stop before the intended end date. Incorrect range selection was also reproduced in the official 1.0.6 APK, but an identical underlying cause has not been established. The current build passes a fast continuous drag and fails a slower drag with valid touch timestamps. Restoring the old gesture attachment does not fix that failure. The strict 38-day assertion remains enabled; this release does not claim a fully passing Android UI suite or a fix for this interaction.

## Platform behavior

Typography, native controls, scrolling and accessibility grouping follow each platform. The shared catalogue exposes the same options on iOS and Android.

| API | Apple | Android |
| --- | --- | --- |
| DynamicList | Cell-ID scrolling and point-offset overloads | Cell-ID scrolling |
| DynamicList scroll animation | Caller animation; distant jumps animate only the final approach | Native animation; distant jumps can take several seconds, and caller duration and curve are not forwarded |
| StackView axis changes | AnyLayout retains child state | HStack/VStack branches can reset child state |
| FrameModifier | Custom Animatable interpolation | Native modifier animations |
| Chevron/Tick thickness and RoundedCorner radius | Interpolate with caller animation | Final geometry updates; custom Shape interpolation is not bridged |
| Checkbox checked-state changes | Caller animation can crossfade the indicator | Indicator updates immediately |
| Transform transition | Translation, rotation and independent scales | Translation and uniform scale |
| Muscle Map accessibility | Named selection actions | Shared region toggles and Compose semantics |
| Codable storage | UserDefaults | SharedPreferences through AndroidUserDefaults |
| Computed binding transactions | Preserve caller animation and transaction metadata | Writes work; SkipFuseUI 1.19 does not expose binding transactions or `withTransaction` |

The `CodableStorage` alias supplies the platform store type for `store:`. Font compression in weekday headers and Xcode previews are Apple-only.

Rating fills and Progress use native trim animations on both platforms. Joystick return uses a value-driven spring. These do not require custom Shape interpolation. The interpolation limitation above was reproduced with SkipFuseUI 1.19.0 and SkipUI 1.61.0; changing a Star's point count or a Triangle's direction is discrete on both platforms.
